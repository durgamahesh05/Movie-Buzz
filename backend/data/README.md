# Data Files

This project uses the MovieLens 25M dataset for database loading, feature generation, and model training. Keep the raw CSV files local; do not commit them to GitHub.

## Where to download the dataset

- Official MovieLens 25M page: `https://grouplens.org/datasets/movielens/25m/`
- Direct ZIP download: `https://files.grouplens.org/datasets/movielens/ml-25m.zip`

The official download is roughly 250 MiB compressed. After extraction, the working CSVs used by this project are roughly 1.1 to 1.2 GiB before any generated train/test splits.

## Files to place in this directory

Extract the MovieLens ZIP so `backend/data/` contains the following raw files:

| File | Needed by current code | Typical size in this project | Notes |
| --- | --- | --- | --- |
| `movies.csv` | Yes | about 3 MB | Required by DB load and training |
| `ratings.csv` | Yes | about 678 MB | Main interaction dataset |
| `tags.csv` | Yes | about 39 MB | Used for tag and sentiment features |
| `genome-scores.csv` | Yes | about 435 MB | Used for genome/tag relevance features |
| `genome-tags.csv` | Yes | about 18 KB | Required alongside genome scores |
| `links.csv` | Optional | about 1 to 2 MB | Safe to keep, but not required by the current training flow |

## Files generated locally by this project

These are outputs of your local pipeline, not downloads:

| File | Generated by | Typical size in this project | Commit to Git? |
| --- | --- | --- | --- |
| `train.csv` | `run_training.py` / `data_pipeline.py` | about 543 MB | No |
| `test.csv` | `run_training.py` / `data_pipeline.py` | about 135 MB | No |

## Expected folder layout

```text
backend/data/
├── README.md
├── movies.csv
├── ratings.csv
├── tags.csv
├── genome-scores.csv
├── genome-tags.csv
└── links.csv
```

`train.csv` and `test.csv` will appear here after you run the training pipeline.

## Quick setup

1. Download `ml-25m.zip` from GroupLens.
2. Extract the CSV files into `backend/data/`.
3. Make sure `backend/.env` points `MOVIEBUZZ_DATA_DIR=./data` if you want the default local layout.
4. Run the trainer from `backend/`.
